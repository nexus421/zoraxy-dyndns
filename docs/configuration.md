# Configuration

Everything is set on the plugin's page in Zoraxy (Plugins, DynDNS Whitelist), see [Usage](usage.md#the-plugin-page).
Every change is checked, saved to `config.json` and applied to the whitelists at once, no restart.

## Clients

- **Name**: the user name in the router. Letters, digits, `.`, `_`, `-`, at most 64 characters, `static` is
  reserved.
- **Access rules**: one or more, picked by name from Zoraxy's access rules. Several clients may share a rule.
- **Password**: generated by the page (24 random bytes as hex) and shown once. Only its SHA-256 is stored, a lost
  password is replaced with "New password", never recovered.

## Access rules

The page lists every rule a client uses plus the rules added with "Manage this rule too" for fixed entries only.
Per rule you set the mode and the fixed entries. "Stop managing" releases a rule without clients: the plugin removes
its own entries there and leaves the switch as it is. A rule added with "Manage this rule too" starts in `warn`, so
adding it never switches a whitelist on.

## Modes

| Mode                | Whitelist has entries        | Whitelist is empty                               |
|---------------------|------------------------------|--------------------------------------------------|
| `enforce` (default) | plugin keeps it **on**       | on, everything blocked                           |
| `warn`              | plugin never touches the switch, only warns while it is off | switch stays as it is |
| `open_when_empty`   | plugin keeps it on           | plugin switches it **off, everything allowed**   |

"Empty" means no IP and no country entries at all, manual ones included. `open_when_empty` is dangerous and must be
set explicitly. A single fixed entry keeps the whitelist closed. If the plugin stops while an `open_when_empty` rule
is open, it stays open until the plugin runs again.

In `enforce` the switch belongs to the plugin: turning the whitelist off in the Zoraxy UI is reverted within 60
seconds.

## Fixed entries

`static` holds entries that are always whitelisted, such as an emergency IP, a VPN range or an office. Private
ranges are allowed, IPv4 /8 to /32, IPv6 /16 to /128. Nothing wider, that would practically switch the whitelist
off. They carry the comment `dyndns:static`.

## Entries the plugin owns

Every entry the plugin writes carries the comment `dyndns:<client>` or `dyndns:static`. Only those entries are ever
changed or removed. Entries with any other comment, the ones you add by hand, are left alone. If a manual entry
already holds an address a client reports, the plugin keeps the manual entry and logs a warning.

Do not give your own entries a comment starting with `dyndns:`, the plugin would treat them as its own.

## config.json

The page writes `config.json` next to the binary (Zoraxy starts the plugin in its folder), owner only (`0600`) and
atomically. Without the file the plugin starts empty. It is read once at startup, strictly: an unknown key, a wrong
type or an invalid value stops the plugin with a message in the Zoraxy log. Edit it by hand only while the plugin is
stopped, the page overwrites changes made while it runs.

```json
{
  "clients": [
    { "name": "fritzbox-home", "password_sha256": "<sha-256 hex>", "rules": ["<rule-id-1>", "<rule-id-2>"] }
  ],
  "rules": {
    "<rule-id-1>": { "mode": "enforce", "static": ["203.0.113.10/32", "10.8.0.0/24"] },
    "<rule-id-2>": { "mode": "open_when_empty" }
  },
  "dyndns_host": "dyndns.example.com"
}
```

`rules` lists rules with a mode or fixed entries, a client's rule that is not listed runs as `enforce` without fixed
entries. `dyndns_host` is optional, a host name with an optional `:port`, only used to show the router settings.

## state.json

Written only by the plugin, next to `config.json` (owner only, atomic rename). It holds the last report of every
client and every rule the plugin has ever managed. That is how it cleans up after a client or a rule was removed
from `config.json`, and how the whitelists survive a restart of Zoraxy or the plugin.

A missing or broken file means an empty state, and the plugin starts anyway. It then knows no reported address: the
next run removes the entries of every client from the whitelists, only fixed entries stay. In `enforce` the protected
services are blocked until each client reports again, which a router may only do when its IP changes. Rules that
were removed from `config.json` but still remembered in the file are no longer cleaned up. Delete the file only
when that is acceptable, and trigger an update on every router right after.

## Warnings

The log and the plugin page warn about settings that weaken a whitelist:

- whitelist off in `warn` or `open_when_empty`
- "allow local and loopback" on: private networks bypass the whitelist
- country entries: they allow whole countries
- access rule IDs in `config.json` that Zoraxy does not know

Each warning is logged once and again only when it changes.

## Command line

Zoraxy starts the plugin itself with `-configure=<json>` (port, API key). `-introspect` prints the self-description
Zoraxy reads before it starts the plugin.
